# Step 003 — browser runtime baseline

Done, 12 November 2026. This is measurement tooling; game artwork is unchanged.
Two complete passes took 161.61 seconds, with zero harness problems or focus losses.
The browser logged one audio error after the final report was saved and the
benchmark printed DONE; it is retained as an unresolved shutdown issue.

## Reproduce

1. `python tools/vo_web.py export`
2. `python tools/vo_web.py serve`
3. Open `http://127.0.0.1:8061/?vo_perf=1` in the built-in browser and keep it visible.

The runner clones the existing Web preset temporarily, enables inclusion of debug
harness scripts, and restores `export_presets.cfg` in a finally block. It exports
the release single-thread template to `build/web_perf/`, preserving the normal
Web output. Music and the existing fullscreen shell/font are copied alongside it.
The URL flag supplies `--scene=vo-perf --passes=2`, 1080p / Mid and isolated
`user://bench/vo/003/` saves/settings. No player data is read or changed.

The browser page prints a compact report and POSTs the full traces to its
same-origin, loopback-only collector. Reports are written atomically to
`build/perf/vo/baseline-web/report.json`. Console output was read with the browser
tool's `tab.dev.logs`, its available equivalent of the runbook's
`read_console_messages`. Runtime: Godot 4.7 release, Emscripten 4.0.20,
Compatibility / WebGL 2, single-threaded, desktop built-in Chromium browser.
The engine reports a 1615×772 window and 2259×1080 3D viewport. The browser's
captured image is 1292×618; report dimensions are the engine's device-pixel sizes.

## Scope, errors and verification

- A packaging preflight initially omitted the on-demand music directory and ended
  in a music-download 404. It was stopped and archived under `preflight/`; support
  assets were repaired before starting the accepted two-pass run. The accepted
  run has no missing-music warnings or GDScript errors.
- “First” means the first visit in the accepted app instance. Browser HTTP and
  driver shader caches were not cleared after that partial preflight, which had
  visited Coastal Path, Cove and the house. These figures therefore **do not
  establish cold-cache first-install stalls**. Step 004 must retain this caveat;
  do not infer shader compilation cost from these transition totals alone.
- This raw export measures runtime and map transitions. It bypasses production
  gzip partitioning/reassembly, so it does not measure production download/startup
  performance. It establishes neither Safari/mobile Web performance nor phone
  WebGL performance. The desktop viewport also differs from step 001's 1920×1080.
- No explicit shader-compilation warning appears in the captured console. After
  `VO PERF WEB saved 2 pass(es)`, JavaScript reported `TypeError: Cannot read
  properties of null (reading 'currentTime')` in `SampleNode._pause` through
  `_godot_audio_sample_set_pause`. Preserve this as an audio shutdown finding;
  its root cause is not established. The two reports were saved before it.
- The local model incorrectly answered that there were no errors. That answer
  was overridden after reading the actual console; see `local-model-triage.txt`.
- Required checks passed: quick (scripts, data, maps, beasts) and vo-perf-route.
  Python syntax checks passed for the three new/changed wrappers. The shared-model
  lock also passed a two-process blocking/release check.
- The repaired export command completed successfully. Its editor scan retains
  warnings about an existing nested `build/cove_verification/project.godot` and
  duplicate audio UIDs among generated build folders; these are distinct from
  runtime console findings. Original generated previews were preserved.
