# Audit of the visual standards and checklist

12 November 2026. This audit covers `standards.md` (the Visual Standards and Whole-Game Overhaul Plan) and `checklist.md` (the Visual Enforcement Checklist). Copies of both are in this folder, unchanged except for a banner that points here. It also records the user's answers to the clarifying questions asked that day. **Where this file and those two disagree, this file wins.**

## Verdict

The two documents get the *what* right. They are sound on principles: forms before texture, quiet surfaces, consistent edges and feature scale, sealed construction, keeping identity, and refusing automation as proof of beauty. They would not, on their own, get an AI agent working in limited sessions to a cozy, beautiful and fast game. Four gaps explain why.

1. **They don't name the actual faults visible in the game today.** Without a concrete diagnosis, each session would rediscover the problems, or polish the wrong thing.
2. **Performance appears only as an approval gate.** The user reports that the game is slow on phone, web, desktop and loading alike. The plan says to "calibrate budgets later" but never says to find and fix the causes. Art built before that work would have to be redone.
3. **They have no unit of work.** Stages A–F are each weeks long. "Convert all families" cannot be finished, or even resumed cleanly, inside one session's limits.
4. **The ledger work is hand-written.** Recording hashes, recipes and fingerprints by hand would use up most of a session's budget before any pixel changed. The user chose to keep the full ledger, so it must be **generated by tools** and only *reviewed* by hand.

## What `docs/performance.md` shows

- Desktop GPU time is low (about 2 ms), so **desktop "slowness" is mostly CPU, loading and stalls**: first-visit shader compilation, construction work and battle start.
- **About 14,500 surfaces have their own soft-finish material** (`surface_finish.gd`). Material and draw-call count is the most likely runtime cost on phones and on Compatibility/WebGL, which has no automatic instancing.
- **First visits on Compatibility hold a black screen for 4–16 s** while shaders compile. Return visits are fast.
- **Phones and a browser export have never been profiled.** Every number is from a Ryzen 7 9700X with an RX 9060 XT.
- The world renders at full window resolution, and `prefs.gd` enlarges low-resolution renders with **nearest** filtering (`prefs.gd:108-110`).

So the performance work starts by measuring on real targets, then cuts materials and draw calls and fixes shader warm-up, *before* new art multiplies the cost.

## Decisions recorded on 12 November 2026

- Palette between soft and contrasty. Our own ground motif. No curved world. Per-biome cliffs.
- Remodel people and beasts, keeping proportions. Blender is OK. Rework first, new packs as a fallback.
- 30 fps on minimum phones and 60 fps on mid-range phones and PC. **Performance foundation first.**
- Full ledger, generated by tools. Small steps of about 1–2 hours. The user approves each step from screenshots.
- AGENTS.md, README Art and the art-direction memory were updated in this session.
- Diagonals (added the same day): building walls, paths, water and all terrain edges may run diagonally, like cliffs. Tiles stay whole: each is walkable or blocked, and diagonal cliff tiles stay unenterable. Every diagonal path is still navigable with four-way movement. Eight-way movement is a Settings option on every platform, **off by default**, with **no corner cutting**. The hero, NPCs and beasts always stop at tile centres. Built in Phase M (`steps.md`).
- Exploration (added the same day): the game has two pillars, exploration and battling. Roads grow 3–4× (the Coastal Path stays the tutorial), with caves, GIANT beasts, goofy puzzles (many required), shortcuts, hot springs and butterflies. Map edges must never show (filler band plus camera clamp). Cogsworth becomes a real cyberpunk city (confirmed). Full design in [exploration.md](exploration.md).
- Interface softening: yes, later (Phase U, after every scene is done). Frames, ornament and finish change; the structure and AGENTS.md interface rules stay.
